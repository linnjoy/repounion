# RepoUnion 界面与交互设计交接

> 这份文档是给界面设计方（Gemini）的完整需求说明。你负责**视觉风格和交互设计**；
> 产品范围、数据和后端由另一方负责，下文「约束」一节列出了不能越过的边界。

## 1. 产品是什么

RepoUnion 是一个 **Windows 桌面程序**（中文界面），给同时维护很多 Git 仓库、很多分支的开发者用。
它是「多仓库状态哨兵 + 快速改动审阅台」，不是完整的 Git 客户端。

用户打开它是为了快速回答四个问题：

1. **哪里还没收尾？** 有没提交的改动、没推送的分支或 stash 的仓库。
2. **有没有在错的分支上改？** 比如直接在 `main` 上改了代码。
3. **agent 刚才动了哪些仓库？** 用户让 AI agent 并行改代码，回来要知道哪些仓库变了。
4. **具体改了什么？** 不想等 VS Code 加载，直接在这里看文本和图片 diff。

使用节奏：一天里频繁切进切出，每次停留几十秒到几分钟。所以**扫一眼就能看懂**比功能多更重要。

## 2. 用户画像

- 专业开发者，熟悉 Git 术语（分支、上游、ahead / behind、stash、worktree），不需要入门引导。
- 一个工作区有十几到几十个仓库；个人项目和公司项目放在不同工作区。
- 屏幕一般是 1920×1080 或更大，但窗口可能只占半屏（最小宽度 1100 px）。
- 习惯键盘操作，F5 刷新，Esc 关闭。

## 3. 现有界面（可以大改）

当前是一个能用但偏朴素的界面：

- 左侧栏：工作区列表，可新建、重命名、删除。
- 主区顶部工具栏：工作区名、汇总数字、按钮「刷新状态」「Fetch 全部」「添加仓库」「添加目录」。
- 筛选条：全部 / 有改动 / 未同步 / 冲突 / 无上游，带数量。另有搜索框。
- 主列表：按「来源目录」分组的**一级列表**（每行一个仓库，不是卡片）。每行左侧有色条，然后依次是：
  仓库名、分支、工作区状态文字、远端状态文字、路径、「⋯」菜单（在资源管理器、终端、VS Code 中打开，从工作区移除）。
- 色条颜色：橙 = 有改动；蓝 = 干净但超前或落后；红 = 冲突或与远端分叉；绿 = 干净且同步；灰 = 干净但无上游。
- 右侧详情面板（点击某一行后出现，可拖动改宽度）：
  - 顶部选择比较方式：工作区 vs HEAD / 工作区 vs 暂存 / 暂存 vs HEAD / 本地 vs 上游。
  - 改动文件按分组列出：冲突、暂存后又修改、已暂存、未暂存、未跟踪、与上游不同。
  - 下方是 diff：文本支持并排和内联、语法高亮、上一处 / 下一处、「n / m 处差异」；
    图片支持并排对比、缩放、适应窗口、实际大小；文件太大或是二进制时显示提示。
- 对话框：添加目录（扫描后勾选仓库，可勾「记为来源目录」）、重命名、删除确认。

现有设计变量（可以替换）：浅色主题，背景 `#eef0f3`，强调色 `#2563eb`，
字体 `Segoe UI` / `Microsoft YaHei`，等宽字体 `Cascadia Mono`。

## 4. 本次要设计的内容

### 4.1 整体视觉

- 浅色和深色两套主题（跟随系统，可手动切换）。
- 风格方向：专业开发工具，信息密度高但不拥挤，接近 Linear、GitHub Desktop、JetBrains 新 UI 的克制风格。
  不要大圆角卡片，不要营销风格的插画。
- 状态色要在深浅两套主题里都清楚，并考虑色弱用户：**状态不能只靠颜色区分**，要配图标或文字。

### 4.2 主列表（最重要）

每行要能在 1 秒内读懂。需要展示的信息，按重要性排序：

1. 仓库名
2. 当前分支；**在保护分支上有改动或本地提交时要明显警告**（新功能）
3. 未提交改动数量（已修改 / 未跟踪分开）
4. 当前分支相对上游：超前 n / 落后 m / 分叉 / 无上游
5. **其他分支上的未推送提交**，比如「另有 2 个分支未推送」（新功能）
6. stash 数量（新功能）
7. worktree 数量，以及其中有改动的数量（新功能）
8. **「有新变化」标记**：上次确认之后，这个仓库的 HEAD 移动了或者改动变了（新功能，对应 agent 场景，需要很醒目）
9. 最后提交时间（相对时间，如「3 小时前」）
10. 路径（次要，可以弱化或悬停才显示）

请设计：

- 单行的布局和列宽在窗口变窄时怎么收缩。
- 每一行在各种状态下的样子：干净同步、有改动、超前、落后、分叉、冲突、无上游、游离 HEAD、
  读取失败、刷新中、Fetch 中、超时。
- 刷新时**逐行出结果**：已出结果的行和还在加载的行要能区分。
- 排序方式（建议：有新变化 > 冲突 / 分叉 > 保护分支警告 > 有改动 > 未推送 > 落后 > 干净），以及按来源目录分组的展示。
- 「标记已查看」怎么操作（单个和全部）。

### 4.3 收工检查视图（新功能）

一个专门的视图或模式，只列出「还没收尾」的东西：没提交的改动、所有分支上的未推送提交、stash、
保护分支上的改动。粒度到**分支**，一个仓库可能出现多条。用户看完之后可以在这里发起批量推送。

### 4.4 批量写操作的确认流程（新功能）

将支持三种低风险写操作：`pull --ff-only`（快进拉取）、`push`（不强制推送）、干净时切换分支。流程是：

1. 用户选择若干仓库，点「拉取」或「推送」。
2. 弹出**预览**：每个仓库一行，显示分支、将拉取或推送的提交数（可展开看提交标题），以及「不能执行」的仓库和原因
   （有改动、不能快进、无上游、在保护分支上等）。
3. 用户确认后逐个执行，每行实时显示进度和结果（成功 / 跳过 / 失败及原因）。
4. 执行时如果发现状态和预览时不一致，会跳过该仓库，界面要把这种情况说清楚。

请设计预览、执行中、执行完毕三个状态。这些操作不可撤销，确认按钮的文字要写明动作和数量，比如「推送 5 个分支」。

### 4.5 详情面板与 diff

保留现有功能，重点优化：

- 文件列表和 diff 区的空间分配（详情面板宽度 480～1200 px 时都要好用）。
- 比较方式切换的表达，让人一眼明白左边是什么、右边是什么。
- 键盘操作：上下键切换文件，`[` / `]`（或其他你推荐的键）跳到上一处 / 下一处差异，Esc 关闭面板。
- 大文件、二进制、读取失败、无改动这些空状态。

### 4.6 其他

- 窗口获得焦点会自动刷新本地状态，需要一个不打扰但看得见的提示（比如「3 秒前刷新」）。
- Fetch 失败或超时的汇总提示，不能遮住列表。
- 工作区设置：保护分支规则（如 `main`、`master`、`release/*`）、来源目录、自动扫描开关、排除清单。
- 首次使用（还没有工作区）的空状态。

## 5. 约束（不能越过）

- 技术栈：Vue 3 单文件组件 + TypeScript + 原生 CSS（全部样式在一个 `src/styles.css`，用 CSS 变量）。
  **不引入 UI 组件库或 CSS 框架**（如 Element、Tailwind），图标如需要可用单个轻量图标集（请说明用哪个）。
- 运行环境是 Windows 的 WebView2（Chromium 内核），不用考虑其他浏览器兼容。
- 界面文字全部用简体中文，Git 术语（HEAD、stash、worktree、Fetch）可以保留英文。
- 列表必须是**一级列表**，不要卡片视图。
- 不能设计超出范围的功能：提交 / 暂存、合并、变基、强制推送、丢弃改动、提交历史浏览、冲突编辑、文件监视。
  如果你觉得某个功能很有必要，可以单独列在「建议」里，不要直接画进主方案。
- 你只负责视觉和交互，**不改数据结构和后端接口**。如需新的数据字段，列在「数据需求」里，由后端评估。

## 6. 希望你交付的内容

1. **设计说明**：视觉方向、配色（深浅两套）、字体与字号层级、间距规则、图标方案，并说明理由。
2. **CSS 设计变量**：可以直接替换到 `:root` 和深色主题选择器里的一组变量。
3. **各界面的布局和状态说明**：4.2～4.6 每一项，配上线框图或静态 HTML 原型（单个 HTML 文件即可，用假数据）。
4. **交互细则**：键盘快捷键表、排序和筛选规则、加载和错误状态、动画时长（如果有动画）。
5. **数据需求清单**：你的设计需要、但第 4.2 节没有列出的字段。
6. **建议**（可选）：范围外但你认为值得做的点。

交付后，开发方会按你的方案改 Vue 模板和 CSS，数据和逻辑由开发方对接。
