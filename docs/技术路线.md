# RepoUnion 技术路线

- 日期：2026-11-25
- 依据：[产品目标](./产品目标.md)
- 基线：PR #3 分支 `cursor/file-diff-view-ed45` @ `c41b5e3`

## 1. 总体判断：保留现有技术栈

| 选择 | 结论 | 理由 |
| --- | --- | --- |
| Tauri 2 + Rust + Vue 3 | 保留 | 安装包约 5 MB，启动快，Windows 上用 WebView2，没有必要换 |
| 调用本机 Git 命令行 | 保留 | 行为和用户命令行完全一致，凭据、钩子、配置都沿用本机设置；不引入 libgit2 |
| `core` 独立 crate | 保留并加强 | 不依赖界面，可以直接单元测试；所有 Git 逻辑和写操作只放在 `core` |
| diff 面板（PR #3） | 保留，作为核心能力 | 产品负责人确认这是必须的功能（VS Code 打开多仓库太慢） |
| CodeMirror 6 | 保留，改成按需加载 | 当前前端包 1.09 MB 是一个整块，语言包应该懒加载 |

2026-11-25 本机核实：Rust 1.100.0（MSVC），`cargo test -p repounion-core` 27 项通过，`npm run build` 通过。

## 2. 代码规范决定

- Rust 遵守 rustfmt + clippy 惯例（snake_case 函数、CamelCase 类型），TypeScript / Vue 遵守社区惯例。
  个人全局规则里的 C++ 前缀命名（`m_`、`p`、`C` 类名前缀）**不用于本项目**：
  Rust 编译器会对这类命名报警告，强行使用会让代码和生态格格不入。
- 保留的规则：注释和提交说明用中文；关键业务规则、边界条件和兼容逻辑必须写中文注释；
  Rust 用 4 空格缩进，前端沿用现有的 2 空格缩进（Vue 社区惯例，避免大面积格式化 diff）。
- 提交作者使用本机 `git config` 中的个人身份，不加任何 agent 尾注。

## 3. 后端架构调整

### 3.1 任务执行器（替代「一次算完再返回」）

新增 `core/src/jobs.rs`：

- 每个仓库一个任务，结果通过 Tauri `ipc::Channel` **逐条推送**给前端，前端逐行更新。
- 每个 Git 子进程有超时：本地状态 15 秒，fetch / pull / push 120 秒。超时就 kill 子进程，该行标记为「超时」。
- 支持取消：前端可以取消正在进行的批次，已在运行的子进程会被 kill。
- 保留全局 8 并发上限（现有 `GitSlot`），去掉 `map_parallel` 和 `GitSlot` 双层限流里多余的那一层。
- 联网命令统一加环境变量：`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=Never`、
  `GIT_SSH_COMMAND="ssh -o BatchMode=yes -o ConnectTimeout=15"`。
  用户已经配置了 `GIT_SSH_COMMAND` 或 `core.sshCommand` 时不覆盖，只在没有配置时设置。

### 3.2 状态模型扩展（解决痛点 a / c / d）

在 `RepoStatus` 上增加字段（每次刷新多 2～3 条轻量 Git 命令）：

| 字段 | 来源命令 | 用途 |
| --- | --- | --- |
| `branches[]`：名称、上游、超前/落后、是否有上游 | `git for-each-ref refs/heads --format=...%(upstream:track)` | 找出非当前分支上的未推送提交 |
| `stashCount` | `git rev-list --walk-reflogs --count refs/stash` | 收工检查 |
| `untrackedFiles` 与 `changedFiles` 分开 | 现有 porcelain v2 解析时区分 | 列表显示更准确 |
| `worktrees[]`：路径、分支、是否有改动 | `git worktree list --porcelain` | 识别 agent 开的 worktree |
| `headOid`、`lastCommitAt` | 现有 `branch.oid` + `git log -1 --format=%ct` | 「有新变化」判断和排序 |
| `onProtectedBranch` | 工作区配置里的保护分支模式 | 痛点 c 警告 |

### 3.3 「自上次确认后的变化」

- 新文件 `%APPDATA%\RepoUnion\snapshots.json`，和 `config.json` 分开，避免频繁写配置。
- 每个仓库记录：确认时的 HEAD、改动文件指纹（路径 + 状态码的哈希）、worktree 列表。
- 刷新后和快照比较，有差异就标记 `changedSinceAck`。用户点「标记已查看」时更新快照。

### 3.4 写操作模块 `core/src/ops.rs`

两阶段执行，防止「预览时」和「执行时」状态不一致：

1. `plan_ops(repos, kind) -> Vec<OpPlan>`：只读。算出每个仓库能不能做、将推送或拉取哪些提交、
   不能做的原因（有改动、不能快进、无上游、在保护分支上等）。
2. `execute_ops(plans)`：逐个仓库先**重新核对** HEAD 和上游 oid 是否和预览时一致，不一致就跳过并报告；
   一致才执行。命令固定为白名单：`pull --ff-only`、`push <remote> <branch>`（无 force）、`switch <branch>`。
3. 每次执行追加写入 `%APPDATA%\RepoUnion\ops.log`（JSON Lines：时间、仓库、命令、前后 oid、结果）。

前端不能拼接任意 Git 参数，只能传 `kind` 枚举。

### 3.5 配置

- `AppState.version` 升到 2，增加 `Workspace.protectedBranches: Vec<String>`（默认 `main`、`master`、`release/*`）。
  读取 v1 时自动补默认值。
- 修复 `save_state` 非原子写入：删掉先 `remove_file` 再改名的写法，直接用 `std::fs::rename` 覆盖
  （Windows 上内部用 `MoveFileExW` + `REPLACE_EXISTING`）。

## 4. 前端架构调整

- `state.ts` 拆成 `stores/workspace.ts`、`stores/status.ts`、`stores/detail.ts`、`stores/ops.ts`，
  继续用 Vue `reactive`，不引入 Pinia（规模还不需要）。
- 状态按仓库 path 存成 Map，逐条更新，避免整表替换引起重绘。
- 窗口获得焦点时自动本地刷新：监听 Tauri 窗口 focus 事件，30 秒内不重复，Fetch 进行中时跳过。
- 仓库超过 200 个时列表使用虚拟滚动。
- CodeMirror 语言包用动态 `import()` 按文件扩展名加载。
- 界面视觉和交互由设计方另行出方案（见 [界面交互交接](./界面交互交接-Gemini.md)）。
  前端结构调整只改数据层，不和视觉改版同时改同一组件。

## 5. 工程配套

- 新增 `rust-toolchain.toml`，固定 `1.100.0`，CI 和本机一致。
- CI 增加 `cargo clippy --workspace -- -D warnings`、`cargo fmt --check`、`vue-tsc --noEmit`。
- README 修正安装包路径：应为仓库根下的 `target/release/bundle/`。
- LICENSE：公开仓库目前没有许可证，需要产品负责人决定（MIT / Apache-2.0 / 保留全部权利）。
