# RepoUnion 产品目标

- 版本：v0.2 规划
- 日期：2026-11-25
- 状态：已与产品负责人（linnjoy）对齐，作为后续开发的范围依据

## 1. 一句话定位

**RepoUnion 是多仓库、多分支开发者的「状态哨兵 + 快速改动审阅台」。**

打开它，几秒内就能知道：哪些仓库有没提交的改动、哪些分支没推送、谁在错误的分支上被改了、
哪些仓库是 agent 刚动过的。还能马上看到具体改了什么，并安全地做低风险的同步操作。

它不是完整的 Git 客户端。真正的提交整理、合并、变基仍交给命令行、IDE 或专门的 Git 客户端。

## 2. 目标用户

同时维护多个项目、每个项目又常常开多个分支或多个 worktree 的开发者。典型特征：

- 手上有十几到几十个仓库，个人项目和公司项目并存。
- 会让多个 AI agent 并行改代码，自己负责审核和收尾。
- 用 VS Code 打开多仓库太慢，不想为了「看一眼改了什么」去等 IDE 加载。

个人仓库和公司仓库**按工作区隔离**：一个工作区只加载自己的仓库，切换工作区就切换整组视图。

## 3. 要解决的痛点（按优先级）

| 编号 | 痛点 | RepoUnion 的回答 |
| --- | --- | --- |
| a | 改完忘了提交或推送 | 列出**所有本地分支**（不只是当前分支）的未推送提交、stash、未提交改动，提供「收工检查」视图 |
| c | 在错误的分支上改了 | 分支名醒目展示；工作区可设「保护分支」（如 `main`、`master`、`release/*`），在这些分支上出现改动或本地提交时高亮警告 |
| d | agent 改了哪些仓库自己没察觉 | 记录「上次确认」时的快照；之后 HEAD 移动、新增改动或新 worktree 的仓库标记为「有新变化」，确认后才消失；识别同一仓库下的多个 worktree |
| e | 提交或推送前逐个核对太繁琐 | 内置快速 diff 面板（文本和图片），不用打开 IDE；推送和拉取支持批量预览后一次确认 |

暂不作为重点：b（远端有新提交还在旧代码上改）靠现有的 Fetch + 落后提示覆盖；f（写日报）暂不做。

## 4. 核心使用场景

1. **开工**：打开工作区，先自动做一次本地刷新，再手动 Fetch 全部，查看哪些仓库落后，再批量 `pull --ff-only`。
2. **agent 跑完一轮后**：切回 RepoUnion，窗口获得焦点时自动本地刷新。列表顶部出现「有新变化」的仓库，逐个点开看 diff，确认无误后标记已查看。
3. **收工检查**：一个视图列出所有「没提交 / 没推送 / 有 stash / 在保护分支上有改动」的仓库和分支，看完一批推送。
4. **随手查看**：点开某个仓库，看改动文件、比较工作区和 HEAD，在资源管理器、终端或 VS Code 里打开。

## 5. 写操作边界

产品负责人接受**低风险写操作**。「低风险」指：不会丢失任何本地改动或提交，且操作前能预览结果。

**允许（规划中，分期实现）**

- `git fetch`（现有）
- `git pull --ff-only`：只在能快进时执行，工作区有冲突风险时拒绝
- `git push`：只推当前已有上游的分支，不加 `--force`；推送前列出将推送的提交
- 工作区干净时切换分支（`git switch`）
- 标记「已查看」等只写 RepoUnion 自身数据的操作

**每次写操作必须**：

1. 先生成「将要做什么」的预览（仓库、分支、提交数），用户确认后才执行。
2. 执行前重新核对状态（HEAD 没变），状态变了就中止该仓库并提示。
3. 写入 RepoUnion 自己的操作日志，便于事后核对。

**明确不做**：强制推送、reset、rebase、非快进 merge、删除分支、丢弃改动、清理未跟踪文件、
在有改动时切换分支、改远端地址。提交（commit）和暂存（stage）暂不做，以后如果要做需重新评估。

## 6. 刷新策略

- 「刷新状态」只读本地，不联网。
- **窗口获得焦点时自动跑一次本地刷新**（有节流，短时间内不重复）。
- 「Fetch 全部」只在用户点击时联网，不自动执行。
- 仍然不做文件系统实时监视。

## 7. 范围外

- 提交历史浏览、文件历史、blame
- 三方冲突编辑
- 任意两个文件或目录的比较、专门的分支对比工具
- 卡片视图
- 「文件检视」（浏览任意文件内容）：仍未授权，需要另行讨论
- 日报生成

## 8. 成功标准

- 50 个仓库的本地刷新在 3 秒内出现第一批结果，结果逐条显示，不必等全部完成。
- 任何一个仓库的 Fetch 卡住都不会拖住其他仓库，单仓库有超时。
- 从「点开仓库」到「看到第一个文件的 diff」不超过 1 秒（普通大小的文本文件）。
- 「收工检查」能找出所有本地分支上的未推送提交，不只是当前分支。
- 所有写操作都有预览、二次核对和日志，没有一种操作会丢失本地改动。
