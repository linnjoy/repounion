## 2. 主列表设计（4.2 核心哨兵视图）

### 2.1 单行信息列结构与响应式收缩规则

单行固定高度 **`44px`**，采用 CSS Grid 精准对齐，确保 1 秒扫读完所有关键哨兵信号：

```text
| 3px色条 | 选框 | 仓库名 + 新变化标识 + 弱化路径 | 分支 + 保护警告 | 工作区改动 | 上游同步 + 扩展哨兵(他分支/stash/wt) | 时间 | 操作 |
|   3px   | 28px |      minmax(190px, 1.4fr)      | minmax(140px,1fr)|   128px   |          minmax(180px, 1.3fr)         | 68px | 60px |
```

**窗口宽度变化时的确定性收缩策略（`1920px → 1100px` 及详情面板打开时）**：
1. **宽屏无详情面板（主区 ≥ 1180px）**：
   - 完整展示全部 10 项信息；路径作为仓库名下方的单行弱化次级文本（`11px`，`--text-muted`，尾部省略），悬停显示完整路径 tooltip。
2. **半屏无详情面板（窗口 `1100px`，主区 ~`880px`）**：
   - 路径自动隐藏，改为**悬停仓库名列时在原地或 Tooltip 显示**；
   - 扩展哨兵徽章（`另有 2 分支未推`、`stash 2`、`wt 3(1改)`）自动切换为紧凑图标缩写（`⎇+2`、`◫2`、`⊞3·1`），悬停出完整中文说明。
3. **详情面板展开时（主列表可用宽度压至 `420px ~ 620px`）**：
   - 自动进入**紧凑哨兵列模式**：保留 `[色条][选框][仓库名 + 新变化][分支 + 保护警告][核心状态摘要(改动/同步)]`，隐藏相对时间与路径列，并将 `⋯` 菜单保留在最右侧，保证不出现横向滚动条。

### 2.2 「有新变化」标记与「标记已查看」交互（Agent 场景）
- **视觉表现**：
  - 行左侧色条变为紫色 `--status-new-bar`，行背景叠加极浅的 4% 紫色洗底；
  - 仓库名紧邻处展示高辨识度胶囊 **`✦ 新变化`**（紫底紫字），悬停浮现具体变化摘要（如：`HEAD c00e963 → 9a41b2e · 改动 +3 文件`）。
- **单行标记已查看**：
  - 点击任意有新变化的仓库行展开详情面板并停留查看时，顶部出现轻量按钮 **`✓ 标记已查看`**（不自动静默消除，防止误触点过错过）；
  - 或在主列表该行悬停时，右侧操作区直接浮现单键 **`✓`（标为已查看）** 图标按钮，点击即刻褪去紫色标记并按规则重新归位（或保持当前位置待下次刷新重排，避免行突然跳走导致误点）。
- **全部标记已查看**：
  - 筛选条右侧在存在 ≥ 1 个新变化仓库时常驻显示 **`✓ 全部标为已查看 (N)`** 按钮，一键清零。

### 2.4 保护分支警告（新功能）
- 触发条件：当前分支命中工作区设置的保护规则（如 `main`、`master`、`release/*`）**且**存在未提交改动或本地未推送提交。
- 视觉表现：分支胶囊升级为红底强边框 **`🛡 main · 保护分支`**，同时左侧色条强制提权为红色（除非已有更高级的新变化紫标，此时保留紫条+红警告徽章）。

### 2.5 逐行出结果的渐进刷新态
- 触发刷新（`F5` / 按钮 / 窗口获焦）时：
  - **已出结果的行**：立即恢复 100% 不透明度，数据更新并伴随极轻的 `160ms` 高亮微闪提示已刷新；
  - **仍在扫描的行**：左侧色条呈流动脉冲态，行内数值保持上一次快照但降为 `50%` 透明并在右侧显示微型旋转指示器（不清空为全白骨架，避免开发者视觉丢失上下文）；
  - 顶栏显示紧凑进度：`正在刷新 7 / 14...`。

### 2.6 来源目录分组头
- 高度 `28px`，`--bg-surface-subtle` 底色，左侧折叠三角 + 目录图标 + 完整路径（等宽 `12px`）+ 仓库总数 + 该组异常微统计（如 `3 有改动 · 1 警告`）；
- 未归属任何来源目录的单独添加仓库统一归入底部 **`独立添加的仓库`** 分组。

## 3. 收工检查视图（4.3 新功能）

入口位于主区顶栏右侧的切换分段器：**`[ 全部哨兵 ] [ 收工检查 (7) ]`**（数字实时显示未收尾条目总数，为 0 时显示绿色对勾 `已全部收工`）。

### 3.1 结构与分支粒度展示

```text

+---------------------------------------------------------------------------------+
| ▸ 🛡 保护分支上的风险改动 (1)                                                     |

|                                                                                 |
```

  - 点击任意条目的 `[查看 Diff]` 直接在右侧滑出详情面板，无需切回主列表。

## 4. 批量写操作确认流程（4.4 新功能）

严格限定三种低风险写操作：**`pull --ff-only`（快进拉取）**、**`push`（普通推送，绝不 `--force`）**、**`干净时切换分支`**。

### 4.1 触发方式
- **主列表勾选**：勾选 ≥ 1 个仓库后，在列表上方滑出紧凑批量操作条：`已选择 5 个仓库 | [ ↓ 快进拉取 ] [ ↑ 推送 ] [ ⎇ 切换分支 ] [ 取消选择 ]`。
- **收工检查视图**：勾选未推送分支后直接点击 `推送 N 个分支`。

### 4.2 弹窗三态设计（宽 `640px`，最大高 `78vh`）

#### 状态 A：执行预览（Preview）
- **顶部说明**：明确声明本次指令（如 `将执行 git push（非强制）`），若是“切换分支”则提供目标分支输入框/下拉选框。
- **可执行区块（绿/蓝标）**：每行显示 `[仓库名] [分支] [↑2 提交 / ↓3 提交]`；右侧提供 **`展开提交 (2) ▾`**，点击内联展开即将拉取/推送的提交标题列表（仅标题+短哈希，轻量只读确认）。
- **不可执行区块（自动折叠或灰底分组）**：明确列出跳过项与原因胶囊，例如：
  - `plc-simulator` — **`工作区有未提交改动`**
  - `coil-vision` — **`与远端分叉，无法快进`**
  - `cmake-toolchain` — **`当前分支无上游`**
  - `qt-scada-core` — **`位于保护分支 main`**
- **底部按钮**：左侧 `[ 取消 ]`，右侧主按钮明确写清**动作 + 数量**，例如：**`推送 4 个分支`** / **`快进拉取 3 个仓库`** / **`切换 3 个仓库到 main`**（可执行数为 0 时置灰禁用）。

#### 状态 B：执行中（Executing）
- 弹窗锁定关闭遮罩（防误关），顶部显示线性进度条 `正在执行 2 / 4...`；
- 列表逐行展示实时状态：
  - 等待中：`○ 排队中`
  - 执行中：`◌ 正在推送 origin/feat/ui-v2...`
  - 已完成：`✓ 成功` / `⊘ 已跳过` / `✕ 失败`

#### 状态 C：执行完毕（Completed）
- 顶部显示结构化汇总条：**`已完成：2 成功 · 1 跳过 · 1 失败`**；
- **状态漂移跳过（关键边界）**：若执行瞬间发现仓库状态与预览时不一致（如 AI agent 刚写入新改动或远端有新推送），该行显示醒目橙灰徽章 **`⊘ 已跳过（状态漂移）`**，下方小字说明：`执行前校验发现工作区已变为有改动，与预览时不一致，为保证安全已自动跳过`；
- **失败行**：展示脱敏精简的 Git stderr 原因，可点击展开完整错误输出；
- 底部提供单键 **`完成并刷新列表`**（自动关闭并同步最新状态）。

## 5. 详情面板与 Diff 审阅台（4.5）

### 5.1 宽度自适应布局（支持拖拽调节 `480px ~ 1200px`）
- **宽模式（宽度 ≥ `740px`）**：左侧为改动文件列表（固定 `240px`，按分组折叠），右侧为 Diff 主审阅区（占满剩余空间），文本并排对比体验最佳。
- **窄模式（宽度 `480px ~ 739px`）**：自动切为上下结构——上方为紧凑文件列表（最大高 `180px` 可滚动 + 可一键折叠），下方全宽展示 Diff（自动优先切为「内联模式」，仍允许手动切回并排）。

### 5.2 比较方向可视化切换器
取代容易混淆的纯文字下拉，采用清晰的 **「基准（左）→ 目标（右）」** 胶囊组，点击切换四项预设，并在下方副行实时标注左右含义：

| 预设标签 | 清晰方向说明（直接展示在 Diff 工具栏左上方） |
| :--- | :--- |
| **工作区 vs HEAD** | `左：HEAD (c00e963)` **`→`** `右：当前工作区` |
| **工作区 vs 暂存** | `左：暂存区 (Index)` **`→`** `右：当前工作区` |
| **暂存 vs HEAD** | `左：HEAD (c00e963)` **`→`** `右：暂存区 (Index)` |
| **本地 vs 上游** | `左：origin/feat/ui` **`→`** `右：本地 HEAD` |

### 5.3 改动文件分组顺序
固定按风险从高到低排列（空分组隐藏）：
1. `冲突`（红标） 2. `暂存后又修改`（橙红双标） 3. `已暂存`（绿标） 4. `未暂存`（橙标） 5. `未跟踪`（灰标） 6. `与上游不同`（蓝标，仅本地 vs 上游模式）

### 5.4 Diff 审阅工具栏与四大空/特殊状态
- **文本 Diff 工具栏**：`[并排 | 内联]` 切换 + 差异导航 `[ ↑ 上一处 ]  2 / 5 处差异  [ ↓ 下一处 ]`（支持 `[` / `]` 快捷键）。
- **图片 Diff 工具栏**：`[并排对比]` + 缩放控件 `[ - ] 100% [ + ]` + `[适应窗口]` + `[实际大小 1:1]`，底部标注左右分辨率与文件大小变化（如 `128×128 (4.2 KB) → 256×256 (9.8 KB)`）。
- **特殊与空状态规范**：
  1. **无改动**：居中展示绿色 `✓` 图标 + `当前比较视角下无差异` + 若当前非默认比较方式则提示一键切回 `工作区 vs HEAD`。
  2. **大文件（如 > 2MB 或 > 10,000 行）**：展示文件体积提示卡片 `文件体积较大（4.8 MB），默认不自动渲染以保持流畅`，提供操作按钮 **`在 VS Code 中打开`**。
  3. **二进制文件**：展示旧/新体积与哈希对比卡片（如 `icon.ico · 二进制文件 · 12.4 KB → 14.1 KB`），提供 `在资源管理器中定位`。
  4. **读取失败**：展示红框提示 + 具体错误摘要（如权限拒绝/编码异常）+ `重试读取` 按钮。

## 6. 其他全局反馈、工作区设置与首次使用空态（4.6）

### 6.1 窗口获焦自动刷新提示
- 位置：主区顶栏汇总数字右侧的轻量状态文本（不弹窗、不抢焦点）。
- 状态流转：获焦触发时显示 `◌ 自动刷新中...` → 完成后变为淡灰字 **`刚刚刷新`** → 随时间温和更新为 **`3 秒前刷新`** / **`2 分钟前刷新`**（悬停显示精确时间戳）。

### 6.2 Fetch 失败或超时的非阻塞汇总条
- 位于主区顶栏与筛选条之间（高度 `32px`，绝不遮盖下方列表）。
- 视觉：浅红/浅橙底 + `1px` 底边框：`▲ 上次 Fetch 有 2 个仓库失败，1 个超时  [ 展开详情 ▾ ]  [ 重试异常项 ]  [ ✕ ]`。
- 点击 `展开详情 ▾` 下拉紧凑清单，逐行列出仓库名、失败类型（认证失败/网络不可达/超时 15s）及单行重试。

### 6.3 工作区设置弹窗
点击顶栏或侧边栏工作区右侧 `⚙` 打开（宽 `540px`，分四个清晰区块）：
1. **保护分支规则**：支持标签式增删通配符（默认预置 `main`、`master`、`release/*`），下方附简短匹配说明。
2. **来源目录**：列出已绑定的来源目录路径，支持 `添加目录` / `移除绑定`（标注不删磁盘文件）。
3. **自动扫描开关**：开关控件 + 说明「打开工作区或手动刷新时，自动发现来源目录下新增的 Git 仓库」。
4. **排除清单**：多行/标签列表，排除指定子目录名或路径（如 `node_modules`、`third_party`、特定归档仓库）。

### 6.4 首次使用空状态（尚无工作区）
当工作区数为 0 时，左侧栏显示极简引导，主区居中展示克制的功能化空态（无营销插画）：
- Union Node 图标（40px）+ 标题 **`开始监控你的本地 Git 仓库`**；
- 一句话说明：`创建工作区并添加本地目录，随时掌握改动、分支风险与 AI agent 变更。`；
- 两个并列操作按钮：主按钮 **`+ 创建工作区并扫描目录`**、次按钮 **`仅新建空白工作区`**。
